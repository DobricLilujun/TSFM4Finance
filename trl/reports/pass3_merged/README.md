# Pass 3 merged: 101 series, 19 models, 3,628 cells

`PASS3_trux_watson.md` is the full per-series table, generated by:

```
python scripts/sweep_evaluate.py --report \
  reports/pass3_trux/lane_cuda-a.jsonl,reports/pass3_trux/lane_cuda-b.jsonl,\
reports/pass3_trux_moment/lane_cuda-a.jsonl,reports/pass3_trux_moment/lane_cuda-b.jsonl,\
reports/pass3_trux_t5retry/lane_t5retry.jsonl,\
reports/pass3_watson/lane_watson.jsonl,\
reports/pass3_trux_ttm/lane_cuda-a.jsonl,reports/pass3_trux_ttm/lane_cuda-b.jsonl,\
reports/pass3_trux_ttm_gpu/lane_ttm_r3_cuda.jsonl \
  --md reports/pass3_merged/PASS3_trux_watson.md
```

Merge is per `(model, series, span, horizon)` with the **newest file winning**, which is
how the run repairs itself: the CUDA `ttm-r3` file supersedes the CPU one, the CPU retry
supersedes the OOM error records for `chronos-t5-base`, and the MOMENT re-run supersedes
the rows that died to the `_pipe_key` bug.

Headline table and its caveats live in `docs/09_benchmark.md` ("What pass 3 shows").
Reproduce the ranking with `probes/trux/rank_pass3.py 'reports/pass3*'/'lane_*.jsonl'`.

(`min_context`). The `ctx` column is per row for exactly this reason.
